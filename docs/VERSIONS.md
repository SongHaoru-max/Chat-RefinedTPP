## Shared capabilities

Both versions provide local accounts and tasks, P2/G2 inputs and validation, explicit run review, fixed scientific execution, run-specific evidence, figures, factual reports and optional model dialogue/interpretation. Both use a built React frontend, FastAPI backend and lightweight LangGraph dialogue orchestration. A model is not required for core analysis.

The supported design is three matched biological replicate pairs: 129/126, 130/127 and 131/128. P1/G1 and the other draft branches are outside these versions.

## Scientific continuity

A direct byte comparison of the supplied archives found **28 scientific/pipeline and plotting Python files unchanged**: all 27 Python files under `pipelines/` and `backend/figures.py`. The reporting, context and installation improvements do not constitute a new P2/G2 statistical or plotting implementation.

This comparison does not establish identical results for every input or environment. Preserve input files, configuration, exact software version and dependencies for reproducibility. PQEs and Site Groups remain the relevant statistical units; they must not be silently reported as unique proteins or definitively localized glycosites.

## Acceptance and verification scope

The maintainer's acceptance is recorded here. Package verification records are historical evidence of the tests actually performed, and include remaining native-platform checks. Acceptance does not imply an independent audit of every feature or certification for every OS, architecture or future Python release.

- Both supplied packages include a built frontend, but no Python interpreter or `.venv`.
- v0.5.0 package records describe Linux checks with Python 3.12 and 3.14. Shell-script availability alone does not establish native macOS verification.
- The package contains Windows-specific path and worker-cleanup protections; this documentation update does not run new Windows, macOS or live-model tests.
- Online model behavior depends on the configured provider. Mock-provider tests do not certify every provider/model combination.
- Report history starts with snapshots generated by the newer version; previously overwritten reports cannot be recovered.

## Future public release records

Once distribution is authorized, publish a version-specific release note with its actual package filename, SHA-256 checksum, source revision, requirements, known limitations and licensing.
